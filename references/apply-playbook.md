# 网申填表手册

来自真实网申，每条都踩过。截至 2026-10-22，覆盖北森 phoenix、智联校园、前程无忧外投页三类站。

## 固定顺序

1. 探测：认页面上的控件，不猜。
2. 映射：标签 → canonical 字段，低置信必须问。
3. 编译：生成动作列表，每个动作带来源路径。
4. 审阅：给人看 diff，掩码。
5. 执行：真实键盘输入，逐动作回读。
6. 核对：刷新或重进，看值还在不在。
7. 记账：写台账。

**执行完不关页面。** 用户要核对，关掉等于把结果藏起来。专用浏览器第一次登录一次，
之后登录状态保留在 `~/.jobpilot/browser`。

**不要跳过第 3 步直接填。** 模型手打的值没有来源，没法核对。

## 真坑清单

### 1. Vue / Element UI：直接赋值不生效

现象：页面上看得见，一保存就没了。
原因：组件的数据来自 `input` 事件，直接改 `value` 不触发。
处理：用真实键盘事件（`press_sequentially` / `type`），填完按 Tab 触发 blur。
默认行为：真实键盘输入，不用配。
测试：`fixtures/element-ui.html` 专门复刻这个行为。

### 2. 点「上一步」回去，表单空白

现象：回退后表单显示空的，吓一跳。
实际：服务器数据还在，只是没回填。
处理：**不要用上一步改数据**。刷新页面，重新进入该步骤。
默认行为：不点「上一步」，回退后刷新重进。

### 3. 保存按钮报错，但其实存上了

现象：`commitOthers is not a function` 之类。
实际：数据已写入，页面提示是假的。
处理：不看弹窗，看结果。刷新/重进，或读列表页。
默认行为：不信弹窗，回读核对。这类文案只记在本地覆盖里，供排查。

### 4. 日期框是只读的

现象：输入不进去，只能点面板。
处理：点开面板，按「年 → 月 → 日」选。
默认行为：检测到只读就点面板。

### 5. 字段有字数上限

现象：学校名限 20 字，英文全称被截断。
处理：优先换短别名（中文名、缩写），**绝不静默截断**。值里可以带 `aliases`。
如果实在没有短写法，停下来问用户。

### 6. 附件有体积/尺寸限制

现象：证件照超过上限，上传失败。
处理：先压到限制以内，再传。压完告诉用户一声。

### 7. 「删除」按钮点了没反应，其实在等确认

现象：点「删除」/「移除」，页面毫无变化，重复点也没用。
原因：按钮是 hover 触发的 Popconfirm，点下去就地弹出「是否要删除该组信息？」+ 是/否，
不点「是」什么都不发生。浮层在视口内，文字进了 `body.innerText`，容易被误判成隐藏模板。
处理：点完立刻截图看同屏浮层；找到「是/确定」点掉再判断成败。
判据：`document.querySelectorAll('.form-item').length` 有没有变少，比看提示可靠。
本地覆盖：可以在 `match.hints` 里记一句。

### 8. 自动解析简历会把不该要的经历一起带进来

现象：上传简历后系统自动生成教育/实习若干块，看着省事。
风险：简历里**已经决定不写的经历**（旧实习、不投的岗位经历）也会一并解析进来；
更隐蔽的是——附件里那份 PDF 本身还带着它，表单删了附件没换，等于白删。
处理：①口径变更后先重出简历文件，再填网申；②解析完逐块核对，删掉不该有的；
③删完回看附件那份 PDF 有没有同样的内容。
配合：`~/.jobpilot/sites/<域名>.json` 里把「上传即解析」的站标注出来。

### 9. 「保存成功」不等于「这一块填完了」

现象：点保存，弹「保存成功」，但右侧/顶部的导航目录仍然标红「未完成」。
原因：保存只做格式校验，必填项空缺不拦。
处理：**不看弹窗，看目录**。每保存一次，回读导航里各模块的完成状态；全绿才算填完。
判据：`未完成` 出现次数归零，比看提示可靠。

### 10. 同名控件必须按序号或语境定位

现象：一个表单里两段教育、两段实习，都有「开始时间」「结束时间」，
按标签找永远命中第一段，第二段填不上。
处理：先把可编辑区按出现顺序编号，用序号定位；每新增/删除一段后**重新读一遍编号**，
不要复用旧下标。按业务键（学校名、公司名）复核，别只信序号。

### 11. 下拉选项必须真实鼠标点击

现象：`li.dispatchEvent(new MouseEvent('click'))` 或 `el.click()` 看着执行了，值没变。
原因：组件把选中逻辑挂在 mousedown/mouseup 的组合上，合成事件不触发。
处理：拿到选项的中心坐标，用真实鼠标点。点之前先 `scrollIntoView`，
在可视区外点不到（尤其长列表、弹层被父容器裁剪时）。
补充：选项面板可能是浮层，父级 `offsetParent` 为 null，用"宽高 > 0"判断可见比用
`offsetParent` 稳。

### 12. 只读日期框：只能走面板，翻页要算差值

现象：日期框 `readOnly=true`，输入不进去。
处理：点开面板，读面板表头的「年 / 月」，用 `目标年×12+目标月 − 当前年×12+当前月`
算出要翻几格，再逐年/逐月点箭头，最后点日。
注意：有些面板有四个按钮（上一年/上一月/下一年/下一月），类名只差 `d-arrow`，
别点错。
注意：「今天/此刻」这类快捷按钮宽度常为 0，点不到，别依赖它。

### 13. 隐藏的 file input 是常态

现象：页面上没有上传按钮的 input，`offsetParent` 为 null，但 `setInputFiles` 能用。
处理：直接按选择器取到元素塞文件，不需要它可见。
注意：**同一页可能有多个隐藏 file input**（证件照、生活照、简历……），
按出现顺序取，并在传完后回读该区域的文案确认落在哪一格。
注意：文件名里带空格、超过 100 字、超过站点上限，会在前端就被拦，报错文案是
「请上传图片」这种含糊话，先按格式和体积自查。

### 14. 简历自动解析 + 手填混用，最容易错的是日期

现象：上传简历后系统解析出教育/实习块，看着都对，于是一路点保存。
实际：解析出来的入学/毕业年份、院系、排名经常是错的或空的，而且不报错。
处理：**解析只当草稿**。逐段核对：起止年月、学历层次、院系、专业、排名、
实习的部门与用工形式。核对完再保存。
配合铁律：口径改过之后先重出简历文件，再上传（见第 8 条）。

### 15. 受控列表选不到全称时，别硬凑

现象：专业全称不在库里，只剩一个近似选项。
处理：选最近的选项，全称写进同一页的「其他 / 补充说明」栏；简历里保留全称。
面试时说明「系统近似填写」。**不要**把全称硬塞进别的字段。

### 16. 整页刷新会丢未保存的编辑态

现象：多模块长表单，填完 A 模块没保存就去填 B，中途刷新或点错导航，A 的内容回滚。
处理：**一块一保存**，保存后再进下一块。不要攒到最后一起交。

### 17. 上传简历前先验内容，别信文件名

现象：目录里那份「XX-中文简历.pdf」名字对、日期新，传上去才发现是旧版，
里面带着已经决定不写的经历。
原因：同一个人手里常有五六份同名简历（不同版本、不同导出时间），文件名不承载版本信息。
处理：**上传前跑一次内容校验**，比如 `pdftotext <文件> - | grep -c <要剔除的关键词>`
必须为 0。更彻底的办法是把本地简历收敛成**唯一一份**，想传错都没得错。
配套：口径一改就重出文件，旧版移进归档目录，不留平行副本。

## 动态表单

- **级联**（省 → 市 → 区）：按路径逐级点，等下一级加载出来再点。计划里存路径，不存选项文本。
- **重复块**（教育、实习、家庭）：按业务键（学校名、公司名）寻址，不按序号。需要新增先点「添加」。
- **多步向导**：每一步单独探测、单独保存；保存后重新探测下一步。
- **条件字段**：某个选项选了才出现。执行完当前页再探测一次，把新出现的字段补进计划。
- **iframe**：先切进去再找控件；探测结果里记 `frame`。
- **受控列表 vs 可自填**：同一个表单里两级字段能力常不同（如「专业类别」可手动添加、
  「专业名称」只能选）。分别试搜索和手动添加入口，别假设。全称选不到时按最近选项填，
  全称留在简历里，面试说明「系统近似填写」。
- **多选面板**（选民族、选标签）：点开不是普通下拉，而是「左侧可勾选列表 + 右侧已选区 +
  搜索框 + 取消/确定」。勾完必须点「确定」才落值，点别处会丢弃。
- **带页签的级联**（籍贯、学校所在城市）：顶层常分「全国 / 国外」两个页签，
  国外是另一套国别列表。选国家前要先切页签，再把目标项滚进可视区。
  点名字只是展开下一级，**要点左侧的圆圈图标才算选中**，最后点「确定」。
- **自动补全**：输入后如果提示「没有搜索到，将使用你输入的学校」，说明这个框允许自由文本，
  直接填中文简称即可，不必迁就列表。
- **联动下拉**：A 选了才加载 B 的选项；A 变一次就要重新读 B 的选项，不要缓存。
  某些 A 的取值下 B 会是空列表，先确认再继续。

## 回读与核对

填完先自己核对，再让用户看。四个动作：

1. **目录全绿**：每个模块的完成状态都不再是「未完成」。
2. **逐块列表回读**：展开每一段（教育、实习、项目、家庭），把标签和值成对读出来，
   跟资料对一遍。不要只看「已保存」。
3. **必填项扫描**：把所有带必填标记的字段找出来，检查有没有值是空的。
   页面顶部显示的「完整度 80%」不能当依据。
4. **有预览走预览**：很多站有「预览」页，那是唯一能一次看到全量落库结果的地方，
   比在编辑态里逐个回读快得多。预览页的文字可以直接整段抓下来核对。

**归档口径**：提交前把预览页的纯文本存一份到本地，出问题时有据可查。

## 提交

- 默认 `dry_run`：填完就停。
- `confirm`：用户明确说投，才点。
- `auto`：只对站点白名单开放，且每次写审计日志。
- 提交前让用户把公司名打一遍，防手滑。
- 提交后立刻记回执号、时间、岗位。

### 「已加志愿」不等于「已投出去」

现象：志愿表里有一条，状态写着「正在申请」，看着像是投了。
实际：这类平台分三段——选志愿 → 填简历 → **完成投递**。前两段做完，
企业一份简历都收不到；页面底部会有一行红字提示。
判据：志愿表的「状态」列变成「已投递」，或页面出现回执号。
处理：填完回头看一眼志愿表状态列，并把这个状态告诉用户——不要替他点，
也不要因为看着有记录就默认投出去了。

### 名额上限以页面文案为准，不按公告猜

现象：同一家集团下总公司、子公司、兄弟公司共用一套登录和一份简历，
但公告里只写总名额或不写。按公告推算经常算错。
处理：登录后看「我的应聘 / 投递记录」页，那里通常会直接写
「最多可投递 N 个公司，总计 N 个职位」和「还可添加 N 个」。
以这行字为准；页面上没有，就按「先投最想去的那个」处理，别赌。

### 集团多入口的判定顺序

1. 域名是否同一个（`xxx.zhiye.com` vs `yyy.zhiye.com`）——同域名基本共用账号与简历。
2. 登录后是不是同一个「我的应聘」列表——是，就共用名额。
3. 公告有没有单独写该主体的限制——有，按公告。
4. 以上都没有 → 按最保守的一档算，并告诉用户"这条我没查到明确写法"。

## 出错了怎么说

| 内部 | 对用户 |
|---|---|
| 找不到控件 | 这一页跟以前不一样了，人家重新认一下 |
| 值对不上 | 你改过资料，人家按新的重新生成一份 |
| 登录过期 | 你的登录掉了，点一下重新进 |
| 验证码 | 这个要你点一下，人家不硬来 |
| 反自动化 | 这个站不让机器看，人家不硬来 |
| 上传超限 | 照片太大，人家压一下 |
| 已加志愿但没完成投递 | 你这边的志愿还挂在「正在申请」，企业还没收到简历 |
| 名额算法不一致 | 这条公告没写清楚，人家按最保守的算，你要是知道准数告我一声 |
| 附件传错版本 | 传错文件了，人家换回正确那份再传一遍 |
