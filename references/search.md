# 找岗与搜索工具

## 推荐顺序

1. **exa**：能搜中文网页、能读正文，接进 Claude Code 当 MCP 用最省事。
2. **DeepSeek 官方 API**：如果你已经在用（有 key），可以直接用它的搜索/抓取接口。
3. 其他能搜中文网页、能读正文的工具。
4. 都没有 → 走下面的降级顺序，照样能干活。

推荐不等于必须。有 key、费用、地区限制，用户自己判断。

## 先说清楚：技能不会自己装

- 不自动装、不改用户的 MCP 配置。
- 用户问怎么装，给官方文档的方向，具体按他用的客户端来。
- 不绑定某一家，也不承诺「装了就能找到好岗位」。

## 什么时候提

**只在第一次找岗、而且手上确实没有搜索工具时**提一次：

> 现在人家只能看你给的链接和官网。要是装个能搜网页的工具，人家能主动翻公告、
> 查公司口碑、比薪资；没有也能干活，就是范围小一点、慢一点。
> 比较顺手的是 exa；如果你已经在用 DeepSeek 官方 API，用它自带的搜索也行。

用户说不装，翻篇，以后不再提。

## 没有工具时的顺序

| 顺序 | 来源 | 覆盖 | 代价 |
|---|---|---|---|
| 1 | 用户给的链接、截图、复制来的 JD | 最准 | 零 |
| 2 | 公司官网校招页（浏览器打开） | 权威 | 一家家翻，慢 |
| 3 | BOSS / 智联（只读浏览） | 面广 | 登录、反爬，只读 |
| 4 | 本地时间线、已有 JD 池 | 不会过期的那部分 | 可能不新 |
| 5 | 用户自己搜一下，把结果贴进来 | 兜底 | 要用户动手 |

**不要因为没工具就不干活。**

## 有工具时

- 搜索只负责“发现”，结论以**官网原文**为准。不要拿搜索摘要当公告。
- 薪资至少两个来源；只有一个就标「估算」，查不到写「缺数据」。
- 公告、截止日、投递入口，尽量回官网核一遍再报。

## 来源质量

| 来源 | 适合确认什么 | 注意 |
|---|---|---|
| 官网公告 / 校招页 | 岗位、截止日、硬门槛、入口 | 最权威 |
| 官方公众号 / 招聘系统 | 批次、流程、笔试安排 | 以官网为准 |
| 招聘平台 JD | 职责、技能、薪资区间 | 可能过期，薪资常是区间 |
| 第三方考情 / 论坛 | 笔试形式、面试轮次 | 标「以官方公告为准」 |
| 聚合站 / 转载 | 线索 | 只作线索，必须回官网 |

## 措辞边界

- 不说「你必须装」「不装就没法用」。
- 不承诺结果，只说范围更大、更快。
- 用户拒绝后不再提；只有他主动问「能不能帮我搜」时再谈。
- 连续几轮因为查不到而交不出结论、用户明显不满意时，可以再提一次。

## 怎么判断有没有

搜索工具是**助手侧**的能力，CLI 看不到 MCP 配置。助手自己检查手上的工具，
有就默默用，没有才按上面的方式提一次。`doctor` 里写「搜索：由助手判断」就是这个意思。
