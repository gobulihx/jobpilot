# 找岗与搜索工具

## 先判断

- 手上有能**搜中文网页、能读正文**的工具 → 直接用，不要问用户「要不要联网」。
- 没有 → **只在第一次找岗时提一次**，不要装完就提，也不要每轮都提。

## 一次性话术

> 现在人家只能看你给的链接和官网。要是装个能搜网页的工具，人家能主动翻公告、
> 查公司口碑、比薪资；没有也能干活，就是范围小一点、慢一点。要装的话，人家告诉你怎么弄。

用户说不装，就翻篇，以后不再提。

用户问怎么装：告诉他这是 Claude Code 的搜索/浏览器工具配置，按那个工具的说明加；
可以举例（exa、DeepSeek Web 之类），但**不绑定某一家，不自动安装，不改用户的配置**。

## 没有工具时的顺序

| 顺序 | 来源 | 覆盖 | 代价 |
|---|---|---|---|
| 1 | 用户给的链接、截图、复制来的 JD | 最准 | 零 |
| 2 | 公司官网校招页（浏览器打开） | 权威 | 一家家翻，慢 |
| 3 | BOSS / 智联（只读浏览） | 面广 | 登录、反爬，只读 |
| 4 | 本地时间线、已有 JD 池 | 不会过期的那部分 | 可能不新 |
| 5 | 用户自己搜一下，把结果贴进来 | 兜底 | 要用户动手 |

每一步都能出结论，只是范围和速度不同。**不要因为没工具就不干活。**

## 有工具时

- 搜索只负责“发现”，结论以**官网原文**为准。不要拿搜索摘要当公告。
- 薪资至少两个来源；只有一个就标「估算」，查不到写「缺数据」。
- 公告、截止日、投递入口，尽量回到官网核一遍再报。

## 来源质量

| 来源 | 适合确认什么 | 注意 |
|---|---|---|
| 官网公告 / 校招页 | 岗位、截止日、硬门槛、入口 | 最权威 |
| 官方公众号 / 招聘系统 | 批次、流程、笔试安排 | 以官网为准 |
| 招聘平台 JD | 职责、技能、薪资区间 | 可能过期，薪资常是区间 |
| 第三方考情 / 论坛 | 笔试形式、面试轮次 | 标「以官方公告为准」 |
| 聚合站 / 转载 | 线索 | 只作线索，必须回官网 |

## 措辞边界

- 不说「你必须装」「不装就没法用」。
- 不承诺「装了就能找到好岗位」，只说范围更大、更快。
- 不替用户改 MCP 配置，也不替他安装。
- 用户拒绝后不再提；只有他主动问「能不能帮我搜」时再谈。

## 什么时候可以再提

只有这几种：

1. 用户主动问「能不能搜一下」；
2. 连续几轮都因为“查不到”而交不出结论，用户明显不满意；
3. 用户抱怨“怎么都是我给链接”。

除此之外，一次就够。
