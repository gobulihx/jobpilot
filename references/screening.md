# 筛岗标准

## 只给三档

- **推荐投**：硬门槛全过，方向和经历对得上，值得花时间。
- **备选**：有一个条件不明确，或方向差一点；条件满足才投。
- **不投**：硬门槛不过，或明显不沉淀能力。

**不要**输出「可以试试」「感兴趣可以投」「看你自己」。用户会直接跳过。

## 硬门槛（逐条对照，不许笼统）

1. 毕业时间：是否在公告写的窗口内。
2. 学历：要求硕士就不能用本科硬投。
3. 专业：公告写「金融、统计、计算机」，你的专业在不在里面。
4. 英语：六级 / 雅思 / 托福的硬线。
5. 应届身份：是否要求未缴社保、未签劳动合同。
6. 地点：是不是硬性限定（多数情况是偏好，不是硬伤）。
7. 薪资下限：低于你的底线就不投；数据不明就标「缺数据」，不要猜。

## 薪资

- 至少两个来源交叉：公告、官网、JD、可靠第三方。
- 只有一个来源，结论标「估算」。
- 区间比单点可靠；只写「面议」就当缺数据。

## 岗位质量

优先能沉淀**可带走的模型、代码、方法论**的岗位：风险计量、模型验证、组合风险、绩效归因、
信用策略、数据分析。

不投：纯报表、纯运营、执行交易、销售型「管培生」、分公司经纪业务储备。

## 典型坑

- 「分公司管培生」在券商里常常是客户开发岗。**先读 JD 正文，再看名字。**
- 「管培生」要问清轮岗多久、能不能回总部、写不写进合同。
- 同一家公司不同批次，要求可能完全不同，以当前公告为准。

## 输出格式

```
[推荐投] 某银行 · 总行风险岗
  · 学历够（硕士 ≥ 硕士）
  · 毕业时间在窗口内
  · 薪资 25–30，两个来源
  · 专业对口
```

理由最多四条，每条一句话。被淘汰的对比对象也要给一句原因。

## 候选清单格式

```json
[
  {
    "company": "某银行",
    "position": "总行风险岗",
    "city": "杭州",
    "degree": "硕士",
    "grad_window": "2026-09-01至2027-08-31",
    "major_req": ["金融科技", "金融"],
    "english": "CET6",
    "salary_low": 25,
    "salary_high": 30,
    "salary_sources": 2,
    "deadline": "2026-10-31",
    "url": "https://..."
  }
]
```

缺的项就省略，不要填 0 或「未知」。缺数据会被判成「备选」，这是有意的。
